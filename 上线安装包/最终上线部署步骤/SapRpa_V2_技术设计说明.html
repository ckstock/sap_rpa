SAP RPA V2 整体架构技术设计

本文描述 V2 在公司 Windows Server 上的本地 API、前端页面、SQLite 主配置源、SAP GUI 串行执行、VBS 参数传入、DingTalk OpenAPI 通知和上线安全边界。设计原则是：浏览器不接触 SAP 密码，SQLite 管业务配置与审计记录，SapWebLauncher 统一承接本机执行能力。

本地 API + 执行器 SQLite 主配置源 SAP GUI 串行资源 DingTalk OpenAPI 通知
1

总体架构

SAP RPA V2 采用“页面 + 本机 API + SQLite + SAP GUI 执行器”的单机优先架构。页面负责交互和提交任务，SapWebLauncher 负责本地 HTTP API、运行队列、SQLite 持久化、VBS 调用、SAP GUI 自动化调度和通知发送。

分层职责

前端 index.html从本地 API 读取事务码、工厂、业务范围、通知机器人、定时任务和运行历史；用户选择参数后提交执行任务。
本地 API由 SapWebLauncher 在 Windows 执行账号下启动，提供配置、任务、队列、运行记录、schema 查看和健康检查接口。
SQLite作为 V2 主配置源和审计记录库，保存业务主数据、事务规则、任务队列、日志、文件和定时任务。
SAP 执行器串行消费 queued run，替换 VBS 参数，调用 SAP GUI Scripting，读取状态栏和脚本输出并回写 SQLite。
通知适配器任务开始、成功、失败后由后端读取本机配置，调用 DingTalk OpenAPI 发送企业消息。

运行拓扑

1. 打开页面用户访问 D:\sap_ai\index.html 或公司门户嵌入页。
2. 读取配置页面调用 http://127.0.0.1:17890/api/config。
3. 创建任务页面提交 POST /api/runs，API 写入 runs。
4. 串行执行执行器按队列调用 VBS 和 SAP GUI。
5. 回写通知结果、日志、文件写入 SQLite，并触发钉钉通知。
核心边界：浏览器只处理业务参数和展示，不保存 SAP 密码、不接收 DingTalk appSecret、不直接操作 SAP GUI。所有本机敏感能力都收口到 SapWebLauncher。
2

SapWebLauncher 本地应用设计

SapWebLauncher 使用 C# / .NET 8 Windows 应用实现，部署在固定 Windows 执行账号下。它既保留 sap-rpa:// 协议唤醒能力，也承担 V2 的本地 HTTP API、SQLite 仓储、执行队列、VBS 运行器和通知适配职责。

本地 API 职责

配置接口提供 /api/config、事务码、工厂、业务范围、规则、机器人、定时任务等配置的读取和保存。
任务接口提供 POST /api/runs 创建 run，GET /api/runs 查询队列和历史，GET /api/runs/{runId} 查看详情。
健康与诊断提供 /api/health、/api/schema 等接口，便于页面和上线检查确认 API、SQLite、队列状态。
接口用途返回核心字段
POST /api/runs创建一次执行任务。API 校验事务码、参数、工厂范围和通知绑定；ZFI072A 多工厂请求生成一个 parent run，并按工厂准备 child run。runId、status、transactionCode、queuePosition、createdAt、childRuns、summaryJson
GET /api/runs查询队列和历史记录，支持按事务码、状态、操作人、日期范围过滤，用于页面列表、前方任务数和审计查询。items、total、runId、parentRunId、status、queuePosition、startedAt、finishedAt
GET /api/runs/{runId}查看单个 run 详情。parent run 返回汇总和 child 明细；child run 返回单工厂执行日志、SAP 状态和输出文件。run、requestJson、summaryJson、logs、files、childRuns、batchItems、notificationStatus
POST /api/runs/{parentRunId}/rerun-failed只重跑指定 parent run 下失败的工厂。API 从原 run_batch_items 读取失败项，新建一次重跑 parent run 和失败工厂 child runs；原 parent 不改回 running，只作为审计记录保留。sourceParentRunId、newParentRunId、rerunOfRunId、plants、childRuns、status、queuePosition
GET /api/config读取页面所需配置，包括事务码、参数定义、工厂、工厂组、事务工厂规则、通知机器人别名和定时任务。transactions、plants、plantGroups、transactionPlantRules、notificationRobots、scheduleTasks、appSettings
GET /api/health健康检查和上线巡检接口，用于确认 API 进程、SQLite、队列 worker、SAP GUI 执行账号状态是否可用。ok、version、dbStatus、queueStatus、runningRunId、serverTime
GET /api/schema返回本机 SQLite schema 和迁移版本，便于联调确认表结构，不返回任何密钥、密码或本机私有配置明文。schemaVersion、tables、columns、indexes、migrations

执行器、SQLite、队列、通知职责

模块职责设计约束
SQLite Repository创建/迁移表结构，读写配置、任务、日志、输出文件、定时任务运行记录。数据库文件位于 D:\sap_ai\data\sap-rpa-config.db，运行库不提交 Git。
Run Queue将 queued 状态 run 串行改为 running 并执行。同一交互式桌面会话只允许一个 SAP GUI 脚本执行，避免窗口和登录态互相干扰。
VBS Runner按事务码找到脚本，替换 {YEAR}、{WEEK}、{PLANTS} 等占位符，捕获标准输出。脚本路径来自配置或默认 D:\sap_ai\transactions。
Notification Adapter根据 run 状态、操作人和机器人绑定选择通知目标，调用 DingTalk OpenAPI。密钥只来自环境变量或 config.local.json，不能下发前端。

核心代码地图

SapWebLauncher 指部署在 Windows 执行账号下的 C# / .NET 8 本地应用工程；代码入口由 Program.cs 承担，工程配置由 SapWebLauncher.csproj 承担，发布后形成 SapWebLauncher.exe。它不是前端页面，也不是单个 VBS，而是把本地 API、SQLite 运行库、串行队列、VBS runner 和 DingTalk 通知统一收口的后端执行器。

代码/文件语言或类型作用

SapWebLauncher.csproj.NET 工程文件定义目标框架、可执行程序输出、SQLite/HTTP/JSON 等依赖和发布参数，是生成 SapWebLauncher.exe 的工程清单。
D:\sap_ai\index.htmlHTML / CSS / JavaScript本地操作台页面，读取 API 配置，提交 POST /api/runs，轮询 run 状态、队列位置、日志和输出文件，不直接保存 SAP 密码或 DingTalk secret。
D:\sap_ai\transactions\ZFI072A.vbsVBScript / SAP GUI ScriptZFI072A 事务脚本，只接收执行器传入的年度、周、工厂等运行参数，驱动 SAP GUI，并把关键步骤、SAP 状态栏和导出结果写到标准输出。
D:\sap_ai\data\sap-rpa-config.dbSQLite 数据库V2 主配置和运行审计库，保存事务配置、工厂规则、runs、run_logs、run_files、通知绑定和定时任务记录。
D:\sap_ai\config.local.json本机 JSON 配置保存只属于当前服务器的运行参数，例如 DingTalk OpenAPI 根地址、appKey/appSecret/agentId、默认目录和联调开关；不得返回前端或提交真实密钥。
%LOCALAPPDATA%\SapWebLauncher\config.jsonDPAPI 保护配置保存 SAP 登录配置，密码字段由当前 Windows 用户的 DPAPI 加密；只能在同一执行账号下解密，供 SapWebLauncher 启动 SAP GUI/VBS 时使用。

执行进度与日志的技术实现

页面截图中的“前方任务数”、步骤状态和黑底日志窗口，底层都来自同一条 run 链路：页面提交 POST /api/runs 后，API 写入 runs 队列表；串行 worker 从 queued 状态领取任务，驱动 VBS，持续把过程日志、文件和通知结果回写 SQLite；页面再通过查询 run 详情和队列状态刷新展示。

1. 创建 run页面把事务码、参数、操作人提交到 POST /api/runs，API 生成 runId，在 runs 写入 queued、排队时间和参数快照。
2. 计算前方任务数API 按 runs 中 running 和更早 queued 记录计算 queuePosition、runsAhead 或 workItemsAhead，页面显示为“前方 N 个任务”。
3. 串行 worker 执行后台 worker 一次只把一个 run 改为 running，占用当前交互式桌面的 SAP GUI 会话，避免多个 VBS 同时抢窗口。
4. VBS 输出日志VBS runner 用 cscript.exe 启动脚本并捕获 stdout，把步骤开始、SAP 状态栏、成功/失败原因解析后写入 run_logs。
5. 文件和通知回写导出的报表路径、大小、类型写入 run_files；成功或失败后调用 DingTalk OpenAPI，并把通知发送结果也写入 run_logs。
页面元素后端来源展示逻辑
前方任务数runs 队列状态和 API 返回的 queuePosition、runsAhead、workItemsAheadrun 仍在 queued 时显示等待数量；变为 running 后显示“正在执行”。
步骤状态runs.status、started_at、finished_at、关键 run_logs页面按 queued、running、success、failed、canceled 刷新步骤节点和结果提示。
黑底日志窗口前端即时日志 + API 返回的 run_logs + VBS stdout 解析结果 + DingTalk 通知日志页面先显示“已提交/排队中/执行器已领取”等本地日志，再合并后端日志，按 INFO、OK、WARN、ERR 着色。
输出文件run_filesVBS 或执行器发现导出文件后写入数据库，页面在 run 详情中展示文件名、路径、类型和大小。
运行方式：SAP GUI 自动化不能作为纯 Session 0 Windows Service 运行。生产建议用任务计划程序，在固定 Windows 执行账号登录后启动 SapWebLauncher.exe --serve。

SQLite 主配置源

SQLite 是 V2 的第一阶段主配置源，承担“业务配置 + 执行审计 + 队列状态”的本地运行库角色。后续可迁移到 SQL Server 或 PostgreSQL，但 API 合同和表语义应保持稳定。

配置与主数据表

表名作用关键说明
plants工厂主数据。保存工厂代码、名称、短名称、启用状态，是工厂选择和规则校验的基础。
plant_groups厂区/业务范围分组。按“平湖三厂/十厂”“全部平湖业务范围”等维护页面选项，可包含业务范围编码。
plant_group_members分组成员关系。维护每个分组包含哪些工厂，以及显示顺序和事务专用顺序。
transactions事务码主数据。保存事务码、名称、阶段、脚本文件、默认运行模式、启用状态、脚本版本/哈希。
transaction_params事务参数定义。保存参数 key、标签、类型、默认值、是否必填、排序；用于页面动态表单。
transaction_plant_rules事务码与工厂规则。保存某事务码允许/默认工厂、固定顺序、分组覆盖规则，例如 ZFI072A 的工厂传入顺序。
notification_robots通知机器人配置。保存机器人别名、供应商、启用状态和非敏感展示信息；secret 不明文回显给页面。
notification_robot_bindings机器人绑定关系。按事务码、工厂组、状态或用户范围绑定通知机器人，决定 run 完成后通知谁。
schedule_tasks定时任务定义。保存任务名称、事务码、参数模板、cron/周计划、启用状态、下次执行时间。
app_settings本机运行设置。保存脚本目录、输出目录、队列模式等非密钥设置；密钥仍优先环境变量或本机私有配置。

运行、日志、文件和定时执行表

表名作用关键说明
runs执行记录和队列主体。每次运行一个 run_id。ZFI072A 多工厂任务使用 parent run 汇总，child run 按单工厂执行；状态流转为 queued、running、success、partial_failed、failed、canceled，并保存 request_json、summary_json、来源 run、SAP 状态和耗时。
run_batch_items拆批明细。记录 parent run 下每个工厂的批次项，包含 parent_run_id、child_run_id、source_parent_run_id、source_batch_item_id、plant_code、sequence_no、status、attempt_no、last_error、开始和结束时间。
run_logs运行日志。记录 API、队列、VBS 输出、SAP 状态栏、通知发送结果，按 run 关联。
run_files输出文件记录。保存导出文件名、路径、大小、类型，供页面展示和后续归档。
schedule_task_runs定时任务触发记录。保存某个定时任务触发出的 runId、触发时间、触发结果、失败原因。
拆批对象设计说明状态与查询
parent run代表用户提交的一次 ZFI072A 多工厂任务，parent_run_id 为空，request_json 保存原始年度、周和工厂列表，summary_json 保存汇总。页面列表优先展示 parent run；全部成功为 success，部分失败为 partial_failed，全部失败为 failed。
child run代表一个工厂的一次真实 SAP GUI/VBS 执行，parent_run_id 指向 parent，request_json 只包含当前工厂和必要业务参数。child run 按普通 run 记录日志、文件和 SAP 状态；失败原因写入自身日志和对应 run_batch_items。
run_batch_items作为 parent 和 child 的稳定映射表，固定工厂顺序、执行次数和失败原因，避免仅靠 JSON 难以查询。用于详情页展示每个工厂状态，也用于 rerun-failed 精确筛选失败工厂。
summary_json保存轻量汇总，例如总工厂数、成功数、失败数、失败工厂、耗时、输出文件摘要和最终通知状态，不保存长日志。供 GET /api/runs/{runId} 和钉钉最终汇总复用，避免每次都扫描完整日志。
来源关系重跑任务在新 parent run 上记录 sourceParentRunId，新 child run 或批次项记录 rerunOfRunId、source_batch_item_id，指向被重跑的原始 child run 和批次项。原 parent run、原 child run 和原批次项只读保留，不因重跑改回 queued 或 running。
迁移策略：V2 第一阶段使用 SQLite 降低部署复杂度；当公司门户接入、多用户并发查询或审计留存要求提升后，可保留 API 合同，将仓储替换为 SQL Server/PostgreSQL。

VBS / ZFI072A / SAP GUI 执行设计

VBS 只负责 SAP GUI 自动化动作和标准结果输出，不负责业务配置决策，也不负责通知。所有可变参数来自页面、API、SQLite 规则和执行器替换。

ZFI072A 参数传入

参数来源执行要求
year页面选择或默认当前业务年。执行器替换到 VBS 占位符，VBS 填入 SAP 对应字段。
week页面选择或周结任务模板。必须与业务周口径一致，写入 runs.request_json 留痕。
plants页面选择 + SQLite 规则计算。ZFI072A.vbs 必须从执行器输入获取，不允许回退到硬编码固定工厂。
businessAreas工厂组和事务规则。ZFI019NL、ZFI080 等需要业务范围的事务使用；ZFI072A 通常以 plants 为主。
STATUS_TYPE=S STATUS_TEXT=SAP 状态栏文本 OUTPUT_FILE=D:\sap_ai\outputs\... ERROR=失败原因
ZFI072A 校验：如果 plants 为空、未替换或缺失，VBS 应输出 ERROR= 并以非零退出，不得自行使用脚本内默认工厂。

ZFI072A 按工厂拆批执行

ZFI072A 多工厂任务不把全部工厂塞进一次 VBS 长运行，而是在 API 和执行器层拆成 parent run + child run。这样单个工厂失败不会吞掉其他工厂结果，页面、SQLite 和钉钉都能给出清晰汇总，并支持只重跑失败工厂。

1. 创建 parentPOST /api/runs 接收年度、周、工厂列表，校验 transaction_plant_rules 后写入 parent run。
2. 生成 child按工厂顺序生成 child run 和 run_batch_items，每个 child 只携带一个 plant。
3. 串行执行队列 worker 一次领取一个 child run，调用 ZFI072A.vbs，避免多个 SAP GUI 脚本抢同一桌面会话。
4. 汇总 parent每个 child 完成后更新批次项、日志、文件和 parent 的 summary_json。
5. 重跑失败rerun-failed 只读取失败工厂，新建重跑 parent run 和失败工厂 child runs，原 parent 作为审计记录不改回运行态。
场景parent run 结果处理方式
全部 child 成功successsummary_json 记录成功工厂、输出文件和耗时，结束后发送成功汇总。
部分 child 失败partial_failed成功工厂结果保留；失败工厂写入 run_batch_items.last_error，页面提供“重跑失败工厂”。
全部 child 失败failed保留每个工厂失败原因，最终汇总标记失败，并允许按失败工厂重新排队。
用户取消或执行器中断canceled 或 partial_failed已完成 child 不回滚；未执行项保持可识别状态，便于人工判断是否重跑。
重跑失败工厂：POST /api/runs/{parentRunId}/rerun-failed 不修改原 parent run 的最终状态，也不把原 parent 改回 queued 或 running。接口只基于失败的 run_batch_items 新建一次重跑 parent run，并为失败工厂生成新的 child runs；新记录通过 sourceParentRunId 指向原 parent，通过 rerunOfRunId 或 source_batch_item_id 指向原失败 child 和批次项。

SAP GUI 串行执行和 /NEX 清理

进入事务已有 SAP 会话时使用 /nZFI072A 或对应事务码进入，减少重复登录。
单队列执行同一桌面会话一次只运行一个 VBS，避免多个脚本争抢 wnd[0]。
读取状态栏关键步骤后读取 wnd[0]/sbar 的 MessageType 和 Text，写入 run。
清理会话执行完成或失败后通过 /NEX 退出/清理 SAP 会话，降低残留窗口影响下次任务。
责任分离：VBS 不读取 SQLite、不访问 DingTalk、不判断通知目标。执行器解析 VBS 输出后更新 runs、run_logs、run_files，再交给通知适配器。
6

DingTalk OpenAPI 通知链路

V2 推荐由本地 API 后端直连 DingTalk OpenAPI 发送通知，不再让 VBS 打开 SAP 事务码或 SAP Gateway OData 做通知推送。这样通知失败不会占用 SAP GUI 串行资源，也更容易做重试和审计。

OpenAPI 调用流程

1. 读取 run获取 runId、事务码、工厂、操作人、SAP 返回消息。
2. 选择机器人根据 notification_robot_bindings 找到机器人别名和接收范围。
3. 获取 token调用 /token 获取 DingTalk OpenAPI token。
4. 发送消息调用 /dingtalk-oa/topapi/message/corpconversation/asyncsend_v2。
5. 写入日志把通知成功/失败写入 run_logs，必要时进入重试队列。
{ "dingTalkOpenApi": { "baseUrl": "<接口根地址>", "appKey": "<appKey>", "appSecret": "<appSecret>", "agentId": "<agentId>" } }

通知策略

开始通知一次parent run 进入队列或被执行器领取时发送一次开始通知，包含事务码、操作人、年度、周、工厂数量和 runId；child run 开始不单独推送。
过程只记日志child run 失败、VBS 警告、SAP 状态栏异常写入 run_logs 和 run_batch_items，页面可查看，但不对每个工厂刷屏通知。
结束汇总一次所有 child run 结束后，根据 parent 的 summary_json 发送一次最终汇总到钉钉，展示成功数、失败数、失败工厂、状态 success/partial_failed/failed、耗时和输出文件摘要。
幂等控制以 run_id + 通知阶段记录发送状态，避免 API 重试、执行器重启或页面重复查询造成重复通知。
降噪原则：ZFI072A 按工厂拆批后，child 失败可以详细记录日志和失败原因，但钉钉只接收开始通知和结束汇总。最终汇总必须由后端通知适配器推送到钉钉，VBS 不直接调用通知接口。

config.local.json 本机保存要求

禁止明文提交：D:\sap_ai\config.local.json 只允许保存在目标服务器本机，用于联调或上线本机配置。该文件可能包含接口根地址、appKey、appSecret、agentId 等敏感信息，不能提交 Git，不能复制到文档附件，不能由 API 明文返回给前端。
配置项推荐来源安全要求
baseUrl环境变量或 config.local.json不要硬编码在前端或公开代码中。
appKey环境变量或本机私有配置仅后端读取，不返回前端。
appSecret环境变量或本机私有配置按密钥处理，不写入 SQLite 普通字段，不提交 Git。
agentId环境变量或本机私有配置可记录别名，真实值仍由后端私有配置管理。
dingTalkUserId登录态、SSO、用户映射临时联调值不能作为正式上线身份来源。
7

部署目录与安全边界

V2 推荐把源码仓库和运行目录分开。源码用于版本管理、打包和同步；运行目录用于服务器本机运行，不把数据库、日志、输出、密钥和 DPAPI 配置带入 Git。

部署/上线目录

路径内容管理方式
D:\sap_ai\index.htmlV2 前端操作台。可从源码同步，页面通过本地 API 获取配置。
D:\sap_ai\bin\SapWebLauncher.exeC#/.NET 8 本地 API 和执行器。由发布包或源码构建产物复制。
D:\sap_ai\data\sap-rpa-config.dbSQLite 运行库。目标服务器本机初始化，不提交 Git。
D:\sap_ai\transactions\*.vbs事务脚本，如 ZFI072A.vbs、ZFI019NL.vbs。从源码同步到运行目录，脚本本身不得含真实密码。
D:\sap_ai\outputs\SAP 导出或结果文件。运行产物，不提交 Git，按审计策略归档。
D:\sap_ai\logs\执行器日志。运行产物，不提交 Git，保留脱敏日志。
%LOCALAPPDATA%\SapWebLauncher\config.jsonSAP 登录配置，密码由 DPAPI 保护。目标 Windows 执行账号本机生成，不跨账号复制。
D:\sap_ai\config.local.jsonDingTalk OpenAPI 本机配置。仅目标服务器保存，不明文提交。

安全边界

Windows 执行账号固定账号登录交互式桌面，运行 SapWebLauncher 和 SAP GUI；不要让多人共用桌面手工操作。
SAP 技术账号SAP 审计显示技术账号，应用侧必须记录真实发起人、部门、事务码、参数和 runId。
API 暴露范围默认绑定本机访问；若开放局域网访问，必须增加认证、端口、防火墙和反向代理策略。
敏感数据SAP 密码、DingTalk secret、导出财务数据、日志中的敏感字段不得提交 Git 或放入公开文档。
上线最小闭环：启动 SapWebLauncher.exe --serve，页面读取 /api/config，提交 POST /api/runs，队列串行执行 ZFI072A.vbs，执行器回写 SQLite 并由后端发送 DingTalk OpenAPI 通知。
