# SAP RPA V2 上线安装文档清单

这份清单用于服务器上线前、上线中、上线后的人工核对。先填清楚路径和 JSON，再部署；不要等任务报错后再倒查配置。

## 1. 上线前参数表

| 勾选 | 项目 | 示例 | 说明 |
| --- | --- | --- | --- |
| [ ] | 固定 Windows 执行账号 | `SR-AIDEMO-T01\Marcus` | SAP GUI、SapWebLauncher、任务计划都必须使用这个账号。 |
| [ ] | 源码仓库目录 | `D:\RPA\RpaProject` | GitHub 拉取目录，只用于 pull、publish、复制发布产物。 |
| [ ] | 运行根目录 | `D:\RPA` | 线上实际目录，页面、API、SQLite、日志、输出都在这里。 |
| [ ] | 后端执行器 | `D:\RPA\bin\SapWebLauncher.exe` | 运行中的 API 必须是这个 exe。 |
| [ ] | 本机 API | `http://127.0.0.1:8080` | SapWebLauncher 默认只监听本机。 |
| [ ] | 对外访问地址 | `https://fi_automation.srv.lstech.com/rpa/` | 正式用户链接；DNS、443、证书、路径前缀和防火墙要单独确认。 |
| [ ] | 兼容访问地址 | `http://10.0.41.158:6174/rpa/` | 保留给内网端口访问和排障；这是 HTTP，不是 HTTPS。 |

## 3. 生产机拷贝清单

从源码或上线包部署到生产机时，按下面清单复制到运行根目录 `D:\RPA`。同一轮发布要保证前端、后端、VBS 和网关来自同一次 Git 提交或同一个上线包。

| 类别 | 源路径 | 生产机目标路径 | 说明 |
| --- | --- | --- | --- |
| 前端入口 | `index.html` | `D:\RPA\index.html` | 页面入口。 |
| 前端脚本 | `assets\js\*.js` | `D:\RPA\assets\js\*.js` | 必须整目录复制，不能只复制 `index.html`。 |
| 网关 | `gateway\rpa-gateway.js`、`gateway\start-rpa-gateway.ps1` | `D:\RPA\gateway\` | 提供 `/rpa/`、HTTP 6174 和 HTTPS 443 入口。 |
| 启动脚本 | `启动脚本\*` | `D:\RPA\启动脚本\` | 服务器重启后启动、检查和 GitNexus 固定入口。 |
| SAP GUI 组件注册脚本 | `启动脚本\00_register_sap_gui_components.*` | `D:\RPA\启动脚本\` | 生产机首次部署或 SAP GUI 重装后，用管理员权限注册脚本组件。 |
| 后端发布产物 | `dotnet publish` 输出目录全部文件 | `D:\RPA\bin\` | 必须先 publish，再复制整个输出目录。 |
| VBS 脚本 | `网页启动登录\transactions\*.vbs` | `D:\RPA\transactions\` | SAP GUI 实际执行脚本。 |
| 事务配置 | `网页启动登录\transactions\transaction-config.json` | `D:\RPA\transactions\transaction-config.json` | 事务码、参数和脚本映射。 |
| 钉钉模板 | `上线安装包\config.local.example.json` | `D:\RPA\config.local.example.json` | 只作为字段说明，不能发送钉钉。 |
| 运维文档 | `SapRpa_V2_功能说明书.html`、`上线安装包\*.md`、`反思.md` | `D:\RPA\文档备份\` 或运维文档目录 | 给上线和排障人员查阅，不参与运行。 |

这些内容必须在生产机本地创建或保留，不要从开发机直接覆盖：

| 路径 | 处理方式 |
| --- | --- |
| `D:\RPA\config.local.json` | 生产机手工填写真实钉钉配置，升级时保留。 |
| `%LOCALAPPDATA%\SapWebLauncher\config.json` | 在生产机固定 Windows 执行账号下生成，不能跨账号/跨机器复制。 |
| `D:\RPA\data\sap-rpa-config.db` | 生产机数据库，升级前备份，默认保留，不要随包覆盖。 |
| `D:\RPA\logs\`、`D:\RPA\outputs\` | 运行日志和导出结果，默认保留。 |
| `D:\RPA\certs\lstech.com\` | 证书私钥/PFX/密码文件只走受控运维渠道，不能进 Git 或普通安装包。 |

### 3.1 整包拷贝 D:\RPA 到生产机

可以把当前 `D:\RPA` 作为部署包整体拷贝到生产机，但要先按下面规则处理：

1. 程序文件可以整包带走：`index.html`、`assets`、`gateway`、`启动脚本`、`bin`、`transactions`、`config.local.example.json`。
2. 生产机专属文件默认不要用测试机覆盖：`config.local.json`、`data\sap-rpa-config.db`、`logs`、`outputs`、`certs\lstech.com`。
3. 如果是全新生产机，拷贝后手工创建真实 `D:\RPA\config.local.json`，重新生成 `%LOCALAPPDATA%\SapWebLauncher\config.json`，重新放置生产证书。
4. 如果是升级已有生产机，先备份已有 `config.local.json`、`data\sap-rpa-config.db`、`certs`，再覆盖程序文件；数据库和真实配置默认保留。
5. 生产机固定 Windows 执行账号必须重新运行 SAP 登录配置脚本，不能直接使用测试机的 `%LOCALAPPDATA%\SapWebLauncher\config.json`。

## 4. SAP GUI 组件注册

生产机首次部署、SAP GUI 重装、手工 SAP GUI 登录正常但网页执行反复登录，或日志看不到 `Detected ready SAP GUI session; skip sapshcut login` 时，先执行：

```text
D:\RPA\启动脚本\00_register_sap_gui_components.cmd
```

这个入口会弹出 UAC，请管理员确认。脚本会定位 SAP GUI 安装目录，注册：

```text
saprotwr.dll
sapfewse.ocx
```

注册后可以只检查状态：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\RPA\启动脚本\00_register_sap_gui_components.ps1" -CheckOnly
```

预期输出里必须看到：

```text
SapROTWr.SapROTWrapper: True
Sapgui.ScriptingCtrl.1: True
SAP GUI scripting COM registration is ready.
```

## 5. 钉钉 JSON 配置

从模板复制生成真实配置：

```powershell
Copy-Item "D:\RPA\config.local.example.json" "D:\RPA\config.local.json"
```

真实文件内容：

```json
{
  "dingTalkOpenApi": {
    "baseUrl": "https://你的钉钉OpenAPI网关根地址/",
    "appKey": "你的真实AppKey",
    "appSecret": "你的真实AppSecret",
    "agentId": "你的真实AgentId"
  }
}
```

`baseUrl` 只填接口根地址。程序会自动请求：

```text
{baseUrl}/token
{baseUrl}/dingtalk-oa/topapi/message/corpconversation/asyncsend_v2?token=...
```

如果日志出现 `sap dingtalk openapi skipped: missing baseUrl/appKey/appSecret/agentId config`，说明运行目录下真实 `config.local.json` 缺失、字段不完整，或者后端没有重启到当前运行目录。

## 6. Git 更新后的发布步骤

`git pull` 只更新源码，不会自动更新线上运行程序。每次更新后按实际改动复制：

后端或 API 有改动：

```powershell
cd /d "D:\RPA\RpaProject"
dotnet publish "D:\RPA\RpaProject\网页启动登录\SapWebLauncher\SapWebLauncher.csproj" -c Release -o "D:\RPA\RpaProject\publish\SapWebLauncher"
Copy-Item "D:\RPA\RpaProject\publish\SapWebLauncher\*" "D:\RPA\bin" -Recurse -Force
```

前端有改动：

```powershell
Copy-Item "D:\RPA\RpaProject\index.html" "D:\RPA\index.html" -Force
Copy-Item "D:\RPA\RpaProject\assets" "D:\RPA\assets" -Recurse -Force
Copy-Item "D:\RPA\RpaProject\gateway" "D:\RPA\gateway" -Recurse -Force
```

VBS 或事务配置有改动：

```powershell
Copy-Item "D:\RPA\RpaProject\网页启动登录\transactions\*.vbs" "D:\RPA\transactions\" -Force
Copy-Item "D:\RPA\RpaProject\网页启动登录\transactions\transaction-config.json" "D:\RPA\transactions\" -Force
```

只重启本项目后端：

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.Name -eq "SapWebLauncher.exe" -and $_.CommandLine -like "*D:\RPA\bin\SapWebLauncher.exe*--serve*" } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }

Start-Process -FilePath "D:\RPA\bin\SapWebLauncher.exe" -ArgumentList "--serve" -WorkingDirectory "D:\RPA"
```

只重启本项目网关：

```powershell
powershell -ExecutionPolicy Bypass -File "D:\RPA\gateway\start-rpa-gateway.ps1"
```

这个脚本只匹配 `D:\RPA\gateway\rpa-gateway.js`，会启动 `http://0.0.0.0:6174/rpa/` 和 `https://0.0.0.0:443/rpa/`。不要停止其他项目的 `node.exe`，不要占用别人已有端口。

`D:\RPA\启动脚本` 是线上运行入口；`D:\RPA\RpaProject\启动脚本` 是 Git 源码副本。两处脚本默认 `RuntimeRoot = D:\RPA`，从源码目录运行也会操作线上运行目录，不是独立测试环境。

服务器重启后直接运行：

```text
D:\RPA\启动脚本\start_sap_rpa_services.cmd
```

启动后检查：

```text
D:\RPA\启动脚本\check_sap_rpa_services.cmd
```

旧 PowerShell、Codex 或任务会话如果识别不到 `gitnexus`，不要重新安装，先用固定入口：

```text
D:\RPA\启动脚本\gitnexus.cmd status
D:\RPA\启动脚本\gitnexus.cmd detect-changes
```

该脚本会自动切到 `D:\RPA\RpaProject`，优先调用 `C:\Users\Marcus\AppData\Roaming\npm\gitnexus.cmd`，PATH 没刷新时也能执行；如果全局 CLI 缺失，则兜底调用项目内 `.gitnexus\run.cjs`。

必须看到三类本项目服务：

| 服务 | 进程/端口 | 说明 |
| --- | --- | --- |
| 本地 API | `D:\RPA\bin\SapWebLauncher.exe --serve`，`127.0.0.1:8080` | 负责队列、SQLite、SAP GUI/VBS 执行和钉钉发送。 |
| HTTP 兼容网关 | `node.exe D:\RPA\gateway\rpa-gateway.js`，`0.0.0.0:6174` | 提供 `http://10.0.41.158:6174/rpa/`。 |
| HTTPS 正式网关 | `node.exe D:\RPA\gateway\rpa-gateway.js`，`0.0.0.0:443` | 提供 `https://fi_automation.srv.lstech.com/rpa/`。 |

## 9. 常见漏项

1. 只有 `config.local.example.json`，没有真实 `config.local.json`。
2. `baseUrl` 填成了 `/token` 或发送接口完整路径。
3. 只 `git pull`，没有 publish 到运行目录 `bin`。
4. 只复制 `index.html`，漏复制 `assets\js`。
5. 只改源码 VBS，漏复制到运行目录 `transactions`。
6. SAP GUI 手工登录正常，但脚本组件未注册，程序检测不到 ready session。
7. 把 SAP GUI 自动化做成普通 Windows Service，进了 Session 0。
8. 重启时误杀其他项目进程或占用别人端口。
9. 证书私钥、PFX 或 `passwd.txt` 被放进 GitHub 或普通用户可读目录。
10. 误以为 `https://域名:6174/rpa/` 可用；6174 是 HTTP 兼容入口，HTTPS 使用默认 443。
11. 改了脚本、配置、网关或上线步骤但没有同步功能说明书和安装清单，导致下一次部署继续踩同一个坑。
12. 浏览器缓存残留旧 `sapRpaApiBase`，导致正式域名页面仍请求旧 IP、旧端口或旧 `/charge`。
13. 整包拷贝 `D:\RPA` 时把测试机 `config.local.json`、SQLite、证书或 `%LOCALAPPDATA%\SapWebLauncher\config.json` 一起当成生产配置覆盖。
14. 内网服务器访问不到证书吊销服务器时，PowerShell `Invoke-WebRequest` 可能报 `CRYPT_E_REVOCATION_OFFLINE` 或 TLS 通道错误；生产检查脚本应使用 `curl.exe --ssl-no-revoke` 做 GET 检查，避免误判 HTTPS 网关不可用。
