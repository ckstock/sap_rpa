# SAP RPA V2 生产部署拷贝清单

本文档专门回答生产机部署时“哪些文件能拷贝、哪些必须本机配置、`D:\RPA\certs` 怎么处理”。它是 `上线安装文档清单.md` 和 `最终上线部署步骤\README_V2_Windows_Server_上线部署.md` 的配套清单。

## 1. 先说结论

可以把 `D:\RPA` 当作程序包整体拷到生产机，但不能把测试机运行状态当成生产状态一起覆盖。

`D:\RPA\certs` 不是技术上“只能安装、不能复制”。它可以在受控运维流程里作为生产证书备份/迁移材料复制，但不能跟普通程序包、GitHub、安装包或聊天附件一起流转。全新生产机必须放生产证书；升级已有生产机必须保留生产机现有证书，不能用测试机证书覆盖。

## 2026-08-06 ALV 组织归档文件边界

保存类 ALV 的本机暂存文件不是生产交付物，也不能跟随程序包复制到生产网络盘。SAP GUI 先写本机暂存，后端按导出 Excel 的实际来源值执行只读 SAP 映射：`ZFI080`、`ZFI080B`、`ZFI019NL`、`ZFI019NA`、`ZFI148` 用 `GSBER -> ZTFI48A-GSBER -> ZBU/ZSBU`；其余保存类用 `WERKS -> ZTFI48B-WERKS -> ZBU/ZSBU`。最终输出为 `<fileStorage.alvExportDataDirectory>\ZBU\ZSBU\yyyy_WKnn\事务码_卡片名称_WKnn.xlsx`，同组织合并，一厂多组织各写一份。只有 SAP 查询成功但无映射时才创建 `<fileStorage.alvExportDataDirectory>\集采工厂\yyyy_WKnn` 回退文件；映射或写入失败时保留本机暂存、任务失败并发钉钉通知。生产拷贝后必须用真实导出验证，不能从测试机复制 Excel 当作验收结果。

## 2. 可以随程序包复制的内容

这些文件来自同一次 Git 提交或同一个上线包，可以复制到生产机 `D:\RPA`：

| 内容 | 目标路径 | 说明 |
| --- | --- | --- |
| 前端入口 | `D:\RPA\index.html` | 用户页面入口。 |
| 前端资源 | `D:\RPA\assets\` | 必须整目录复制，不能只复制 `index.html`。 |
| 网关脚本 | `D:\RPA\gateway\` | 提供 `/rpa/`、HTTP 6174、HTTPS 443 入口。 |
| 启动脚本 | `D:\RPA\启动脚本\` | 启动、检查、SAP GUI 组件注册、GitNexus 固定入口。 |
| 后端发布产物 | `D:\RPA\bin\` | 必须复制 `dotnet publish` 输出的完整目录，不要只换 exe。 |
| SAP NCo 依赖 | `D:\RPA\依赖\SapNco\` | 包含 `sapnco.dll`、`sapnco_utils.dll`、`ijwhost.dll`、`cpc4n.dll`。 |
| 事务脚本 | `D:\RPA\transactions\` | VBS 和 `transaction-config.json`。 |
| 配置模板 | `D:\RPA\config.local.example.json` | 只能做字段说明，不包含真实密钥。 |
| 运维文档 | `D:\RPA\文档备份\` 或运维目录 | `SapRpa_V2_功能说明书.html`、上线 Markdown、`反思.md`、交接文档。 |

## 3. 不能用测试机覆盖的生产状态

这些内容必须在生产机本机创建、填写、保留或通过受控渠道迁移：

| 内容 | 路径 | 处理规则 |
| --- | --- | --- |
| 真实本机配置 | `D:\RPA\config.local.json` | 生产机手工填写真实钉钉、SAP NCo、ZFI057 memory fetch、ALV 保存路径；升级时默认保留。 |
| SQLite 数据库 | `D:\RPA\data\sap-rpa-config.db` | 生产业务配置、定时任务、运行历史来源；升级前备份，默认保留，不随包覆盖。 |
| 日志与输出 | `D:\RPA\logs\`、`D:\RPA\outputs\` | 排障证据和输出结果；默认保留。 |
| ALV Excel 输出 | `fileStorage.alvExportDataDirectory` 指向的目录 | 生产输出目录只由生产配置决定，不随测试机结果迁移。 |
| SAP 登录配置 | `%LOCALAPPDATA%\SapWebLauncher\config.json` | 必须在生产机固定 Windows 执行账号下用 `04_配置SAP登录信息.bat` 重新生成，不能跨机器/跨账号复制。 |
| HTTPS 证书 | `D:\RPA\certs\lstech.com\` | 只允许受控证书渠道或生产备份迁移；不能进 Git、普通安装包或公开共享目录。 |

## 4. `D:\RPA\certs` 处理规则

`D:\RPA\certs` 里通常包含证书、公钥链、私钥、PFX 和密码文件。私钥/PFX/密码文件属于 secret。

全新生产机：

1. 由运维提供生产域名证书，域名必须覆盖 `fi_automation.srv.lstech.com`。
2. 放到 `D:\RPA\certs\lstech.com\`，文件名和网关脚本配置保持一致。
3. 设置 ACL，只允许生产执行账号、Administrators、SYSTEM 读取。
4. 启动网关后检查浏览器无证书告警，HTTPS 页面和 API 都返回 200。

已有生产机升级：

1. 升级前备份 `D:\RPA\certs\lstech.com\`。
2. 覆盖程序文件时排除 `D:\RPA\certs\`。
3. 除非证书到期或域名变更，不替换生产证书。
4. 如果必须换证书，先停网关，替换证书，重设 ACL，再启动并验收 HTTPS。

灾备或迁移：

1. 可以从生产证书备份复制 `D:\RPA\certs` 到新生产机，但这属于证书迁移，不属于普通程序复制。
2. 复制过程必须走受控运维通道，不能进 GitHub、普通 zip 包、企业聊天明文附件或个人目录。
3. 复制后必须重新设置 ACL，并确认网关运行账号能读证书。

ACL 示例：

```powershell
icacls "D:\RPA\certs\lstech.com" /inheritance:r
icacls "D:\RPA\certs\lstech.com" /grant "Administrators:(OI)(CI)F" "SYSTEM:(OI)(CI)F" "<生产执行账号>:(OI)(CI)RX"
```

验收示例：

```powershell
curl.exe --ssl-no-revoke -I "https://fi_automation.srv.lstech.com/rpa/"
curl.exe --ssl-no-revoke -I "https://fi_automation.srv.lstech.com/rpa/api/health"
```

`--ssl-no-revoke` 只跳过内网 CRL/OCSP 吊销查询，不跳过证书链和域名校验。浏览器仍必须无证书告警。

## 5. 全新生产机部署顺序

1. 固定 Windows 执行账号登录交互式桌面。
2. 用 `ipconfig` 或 `Get-NetIPAddress -AddressFamily IPv4` 确认本机 IPv4。正式系统 IP 是 `10.0.2.120`，HTTP 兼容入口应验收 `http://10.0.2.120:6174/rpa/`。
3. 安装 SAP GUI，启用 SAP GUI Scripting。
4. 复制程序包允许复制的内容到 `D:\RPA`。
5. 放置生产证书到 `D:\RPA\certs\lstech.com\`，设置 ACL。
6. 复制 `D:\RPA\config.local.example.json` 为 `D:\RPA\config.local.json`，填写真实钉钉、SAP NCo、ZFI057 memory fetch、`fileStorage.alvExportDataDirectory`。
7. 用固定 Windows 执行账号运行 `D:\RPA\RpaProject\上线安装包\04_配置SAP登录信息.bat` 或运行目录对应脚本，生成 SAP 登录配置。
8. 用管理员权限运行 `D:\RPA\启动脚本\00_register_sap_gui_components.cmd` 注册 SAP GUI 脚本组件。
9. 执行 `D:\RPA\bin\SapWebLauncher.exe --init-db` 初始化或迁移数据库。
10. 运行 `D:\RPA\启动脚本\start_sap_rpa_services.cmd -HttpCompatibilityHost 10.0.2.120` 启动本项目；联调服务器则使用 `10.0.41.158`。
11. 运行 `D:\RPA\启动脚本\check_sap_rpa_services.cmd -HttpCompatibilityHost 10.0.2.120` 检查 Local API、HTTPS portal、HTTPS API proxy、HTTP compatibility portal。
12. 从正式页面提交一个受控任务，确认 SQLite、日志、钉钉和保存类 Excel 输出都落到生产目录。

## 6. 已有生产机升级顺序

1. 停止本项目 `SapWebLauncher.exe --serve` 和 `rpa-gateway.js`，不要影响其他端口或其他项目。
2. 备份生产状态：`D:\RPA\config.local.json`、`D:\RPA\data\sap-rpa-config.db`、`D:\RPA\certs\lstech.com\`。
3. 覆盖程序文件：`bin`、`assets`、`gateway`、`启动脚本`、`transactions`、`config.local.example.json`。
4. 不覆盖生产机自己的 `config.local.json`、SQLite、证书、日志、输出目录和 SAP DPAPI 登录配置。
5. 执行 `D:\RPA\bin\SapWebLauncher.exe --init-db`，只做保留历史数据的迁移。
6. 重启本项目服务。
7. 运行检查脚本和真实页面受控任务验收。

## 7. 回滚原则

回滚时只回滚程序文件和前端/VBS/网关脚本；生产 `config.local.json`、SQLite、证书、日志、输出目录默认不回滚、不删除。

如果新版本数据库迁移已执行，先确认旧版本是否兼容新字段。没有把握时，使用升级前备份的 SQLite 回滚，并记录会丢失哪些升级后运行历史。

## 8. 提交和打包禁区

提交 GitHub 或制作普通程序包前，必须确认不包含：

```text
D:\RPA\config.local.json
D:\RPA\data\sap-rpa-config.db
D:\RPA\logs\
D:\RPA\outputs\
D:\RPA\certs\
%LOCALAPPDATA%\SapWebLauncher\config.json
真实钉钉 appKey/appSecret/agentId
SAP 用户密码
导出的 Excel 报表
```
