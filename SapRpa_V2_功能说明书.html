1

功能范围

SAP RPA V2 用于在公司 Windows Server 上集中执行 SAP GUI 自动化任务。业务人员在页面选择事务码和工厂，系统把任务写入本地 API 队列，由服务器上的 SapWebLauncher 串行调用 VBS 和 SAP GUI 完成操作，并把结果、日志、文件和通知状态写入 SQLite。

V2 同时包含服务器上线安装包和部署步骤。当前安装包不再提供一键安装器，正式交付方式是“手工安装指南 + 上线核对清单 + 必要脚本”；不得把当前开发机路径当作正式服务器前提。

使用对象

业务执行人员发起事务码任务、查看执行进度、接收钉钉通知、下载或追溯结果。
配置维护人员维护工厂、业务范围、事务码、事务码与工厂规则、定时任务。
系统管理员按手工安装清单部署 SapWebLauncher、配置 SAP 登录信息、初始化 SQLite、核对运行目录、检查队列和服务状态。

系统边界

安全边界：浏览器页面不保存、不接收 SAP 密码；钉钉 appKey、appSecret、agentId 和 SAP 登录配置只允许保存在服务器本机环境变量、config.local.json 或 DPAPI/Windows 凭据管理器中，不返回前端，不提交 Git。
范围V2 当前支持不做或后续再做
事务执行ZFI072A 优先打通；其他事务码可配置展示，但脚本未验证前不作为生产自动化承诺。不并发操作同一个 SAP GUI 桌面会话。
配置源SQLite 是当前主配置源，页面从 API 读取。SQL Server/PostgreSQL 可作为后续迁移目标。
身份与通知页面可从对方平台 URL token 解析钉钉 ID 和姓名；执行页复选框勾选时使用联调默认 11464769，取消勾选时必须使用本次 URL token 的钉钉 ID，未解析到钉钉 ID 则禁止提交。正式身份应由公司门户 URL token 或 SSO 交给 API 侧验签确认。

页面入口

用户打开正式入口 https://fi_automation.srv.lstech.com/rpa/ 后进入本地操作台；兼容排障入口按目标服务器 IPv4 生成，格式为 http://<服务器IP>:6174/rpa/。当前联调服务器示例为 http://10.0.41.158:6174/rpa/，正式系统 IP 为 10.0.2.120，正式系统兼容入口应为 http://10.0.2.120:6174/rpa/。所有真实配置、执行和历史数据都通过服务器本机 http://127.0.0.1:8080 的 API 获取，并由 D:\RPA\gateway\rpa-gateway.js 代理到当前访问域名的 /rpa/api/*。当前前端入口由 index.html 和同目录 assets/js/*.js 共同组成；运行目录缺少 assets/js 时，页面可能白屏、下拉不刷新或按钮无响应。

产值拆分链路（ZFI057 单入口，后台三步）

ZFI057 东台业务范围与物料取值业务规则

“东台”是物料取值口径，不是工厂名称。系统对本次步骤一的每个业务范围 S_GSBER，只读查询 SAP 表 ZTFI48A：以 ZTFI48A-GSBER=S_GSBER 精确匹配，并检查返回的 ZTFI48A-ZSBU 是否含“东台”。同一业务范围存在多条映射时，任一条 ZSBU 含“东台”即按东台口径处理；未匹配记录或所有 ZSBU 均不含“东台”即按非东台口径处理。

ZFI057 TBTCO 失败边界：10 分钟内没有收敛、匹配不到预期 job、或匹配到失败终态时，当前业务范围失败并保留作业号与 SM37 排查信息；第二次 ZCO020 只在第一批预期 job 全部 F(finished) 后执行。第二次若仍筛出数据并保存，可能创建第二批 job；该第二批 job 按当前业务规则不再轮询。

批次文件父 run 完成时不再合并跨工厂总 Excel，而是读取所有 child 的 run_files，把每个工厂自己的最终 Excel 逐个登记到父 run 的 run_files。同一个 child 如果存在 _part1/_part2，会先在该工厂目录内合并成一个最终工厂 Excel，再登记父 run。业务范围 child 如果导出的是包含多工厂的原始 ALV，后端会按 Excel 工厂字段拆成多个工厂文件后再登记；拆分成功后 raw 文件、业务范围子目录和空的 _raw_business_area 根目录会清理。如果业务范围导出只有表头或没有工厂数据行，raw 文件和空目录也会清理，父子 run 不登记无用文件，且不会因为“没数据”被判为技术失败。因此父任务结果里只会看到真实拆出的工厂文件，文件夹也按工厂拆开；不再生成 yyyy_WKnn\事务码_卡片名称_yyyyMMddHHmmss.xlsx 这种跨工厂总表，也不再生成“合并数据”“合并异常”或“分片清单”工作簿。
成功判断当前以 VBS 完成流程、ALV 分片文件落盘、SAP 状态栏消息、脚本退出码和执行器记录为依据；对 ZFI072A，ALV 导出文件确认完成即该工厂成功，不再强制等待后续 SAP 保存按钮；对 ZFI072N，必须先完成 ALV 分片导出，再继续全选并执行原有 SAP 保存动作。对 ZFI019NL，查询阶段 SAP 状态栏明确提示“没有符合条件数据”或导出的业务范围 Excel 只有表头时，按无业务数据处理，输出 warning/成功标记并清理 raw 临时文件，不作为技术失败。
Excel 清理SAP GUI 标准 Excel 导出通常会短暂打开 Excel。VBS 导出完成后按本次分片完整路径关闭对应工作簿；如果 Excel 没有把工作簿注册到 COM，VBS 会通过 WMI 查询 EXCEL.EXE 的 CommandLine，只终止命令行包含本次分片完整路径的 Excel 进程，并确认该路径不再被 Excel 打开后才输出 OUTPUT_FILE、继续下一个日期段或工厂。父 run 结束时后端从 child run 的 run_files 读取实际分片完整路径，并只对这些路径调度 Excel 关闭 helper；helper 同样带路径级 WMI 兜底。禁止按进程名粗暴关闭全部 Excel，避免影响用户手工打开的其他工作簿。
结束清理每个任务完成后应通过 SAP GUI 执行清理逻辑，优先对已登录 session 发送 /NEX，并遍历多个匹配 session；对没有命令框的登录前窗口或弹窗尝试关闭并记录日志，避免服务器桌面堆积窗口。
生产文件落盘口径：所有保存类 ALV 卡片（ZFI072A、ZFI072N、ZFI057、ZFIR034、ZFI080、ZFI080B、ZCO019、ZFI019NA、ZFI019NL、ZFI148）以及 ZFI057 步骤一物料清单 Excel，均先写入本机暂存目录 D:\RPA\临时文件\ALV本地暂存，不把 UNC 网络路径直接传给 SAP GUI。后端在确认 OUTPUT_FILE 或服务端生成的工作簿、文件存在且大小稳定后，按 Excel 实际 WERKS 或 GSBER 查 SAP 组织映射；ZFI057 物料清单按业务范围 scope 查 ZTFI48A，再归档到 fileStorage.alvExportDataDirectory 的 ZBU\ZSBU\yyyy_WKnn 或 集采工厂\yyyy_WKnn。复制完成后校验最终文件存在和大小，再删除本机暂存文件及空目录。归档失败时 child run 必须标记为 failed、写入 ERROR 日志、保留暂存文件供排障，并进入钉钉失败通知；不得把“SAP GUI 已导出”误判成整个卡片成功。

多工厂拆批与失败重跑

当 ZFI072A 一次选择多个工厂时，推荐按“父 run + 工厂子 run”执行。父 run 表示用户的一次业务请求，子 run 表示每个工厂的实际执行结果。这样可以避免 A、B、C 分批执行时只有 B 失败，却无法准确追溯或重跑。

状态含义用户处理
success所有工厂执行完成。查看日志、文件和钉钉汇总。
no_dataSAP 已正常执行，但该工厂或批次没有符合条件的数据；不生成空 Excel，也不属于失败。钉钉显示“自动化已完成（无数据）”。无数据项不进入“失败工厂”重跑范围。
partial_failed部分工厂成功，部分工厂失败。优先使用失败工厂重跑，不重复执行已成功工厂。
failed任务整体失败或所有子任务失败。按异常 SOP 检查 SAP 登录、脚本、工厂数据量或输出文件。
重跑失败工厂POST /api/runs/{parentRunId}/rerun-failed 根据失败工厂创建新父 run。只重跑失败工厂，保留原 run 审计记录。

跨事务链路与 result 传参

对于“先跑报表 A、报表 B，计算 A+B 的最终 result，再把 result 和页面工厂入参一起传给报表 C”的场景，V2 应采用父子 run 或 chainRun 编排。父 run 表示一次链路请求，子 run 分别表示 A 取数、B 取数、result 计算、C 执行。

步骤责任方数据要求
A/B 报表取数后端通过本地 SAP NCo 报表取数工具、ZFM_NCO_SUBMIT 或等价服务取回 list/spool 数据。原始 A/B 结果必须关联 runId 保存，不能只写进页面黑底日志。
result 计算后端或后台 worker 做清洗、匹配、合并、冲突处理和空值处理。必须明确字段映射：A 哪些字段、B 哪些字段、合并公式、格式转换、空值规则和冲突规则。
result 落库/落盘小结果写 SQLite 结构化字段；大结果写 outputs/<runId>/result-for-C.json、CSV 或 XLSX。C 不从页面临时状态、截图或黑底日志推断 result，只接收 resultId 或 resultFile。
C 执行若 C 可后台执行，优先 NCo/ABAP；若必须操作 SAP GUI，则 SapWebLauncher 串行调用 C 的 VBS。C 入参包含页面工厂参数 + resultId/resultFile，大结果不得塞进 URL 或命令行。
重跑可重跑失败步骤。C 重跑必须绑定同一版 A/B result，或先重新执行 A/B 生成新版 result，不能混用旧 result。
链路门槛：C 只能在 A/B 都成功且 result 必填字段校验通过后执行。A/B 取数失败、result 缺字段或 C 入参校验失败时，链路状态应为 failed 或 partial_failed，不得误标成功。

基础配置

基础配置采用后台管理风格，目标是高效维护数据。页面只在 API 在线时允许新增、编辑、删除；离线时仅显示示例或缓存数据。

工厂与业务范围

配置项用户维护内容影响范围
工厂配置工厂代码、名称/说明、所属业务范围、排序、启停。影响事务码规则、执行页工厂列表、定时任务工厂范围。
业务范围配置业务范围 ID、名称、短名称、包含工厂、部分事务专用业务范围或工厂覆盖。执行任务时根据事务码和业务范围自动带出工厂。

事务码与工厂/业务范围规则

规则用于定义某事务码默认选择哪个业务范围，以及最终传给 VBS 的工厂列表。用户选择业务范围后，页面应自动带出对应工厂，并允许在规则维护中增删工厂。最终执行时以事务码规则解析出的工厂列表为准。规则弹窗新增工厂后会即时显示工厂标签和由工厂主数据推导的关联业务范围；输入框只在新增成功后清空。规则允许先保存有效 SAP 工厂代码，再补充门户工厂主数据；主数据缺失或缺少业务范围时页面会显示缺失提示，不会静默删除该规则代码。

日期范围事务：ZFIR034 只接收 period 和 weekEnd，不接收工厂或业务范围，也不要求用户手工输入周次。页面、API、定时任务触发器按运行时服务器系统日期计算上一完整自然周，周一作为开始日期、周日作为截止日期；VBS 在 SAP 选择屏幕写入 S_BUDAT-LOW/HIGH，并按最终开始日期推导年度和周次写入 P_GJAHR/P_WEEK。执行后导出 ALV Excel，本机暂存后按 Excel 实际 WERKS/工厂 组织归档。例如系统日期为 2026-07-02 时，执行日期范围为 2026.06.22 至 2026.06.28，P_GJAHR=2026、P_WEEK=26。钉钉通知只展示该日期范围。
配置源规则：API 在线时，配置来自 SQLite；页面不应以旧静态数组作为生产配置依据。API 离线时的 fallback 只用于演示和只读预览。

删除、停用和前端刷新

基础配置的红色操作统一为“删除”，不是“停用”。删除成功后页面立即移除该行，再刷新 GET /api/config 校验最终状态。后端从 SQLite 删除配置并写入删除标记，避免服务重启或播种配置后又恢复为默认项；历史 runs 保留用于审计。被定时任务、排队/执行中的任务、关联规则或机器人绑定引用的配置会返回 409，页面保留该行并提示先清理引用。

操作行为注意事项
新增/编辑调用对应配置 API，保存后刷新 GET /api/config。保存失败时不得只改页面内存。
删除工厂/业务范围/机器人从相应 SQLite 配置表真正删除，并保留删除标记。有关联的业务范围、规则、定时任务或机器人绑定时拒绝删除并返回 409。
删除事务码/规则事务码删除会一并清除同事务码的规则、脚本缓存和机器人事务绑定；单独删除规则不会删除事务码。事务码被定时任务或排队/运行中的 run 引用时拒绝删除；已完成 run 历史保留。

A/B 报表取数合并后驱动 C

页面提交页面只提交工厂、期间、事务链路等业务参数，API 创建父 run。
