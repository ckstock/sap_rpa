SAP RPA V2 功能说明书

本文面向业务使用者、实施人员和后续 AI 接手者，说明 SAP RPA V2 每个页面入口、按钮行为、数据落点、状态含义、执行链路、异常处理和验收方式。技术细节详见同目录的 SapRpa_V2_技术设计说明.html。

本地 API SQLite 主配置源 SAP GUI 串行执行 钉钉通知
1

功能范围

SAP RPA V2 用于在公司 Windows Server 上集中执行 SAP GUI 自动化任务。业务人员在页面选择事务码和工厂，系统把任务写入本地 API 队列，由服务器上的 SapWebLauncher 串行调用 VBS 和 SAP GUI 完成操作，并把结果、日志、文件和通知状态写入 SQLite。

V2 同时包含服务器上线安装包和部署步骤。当前安装包不再提供一键安装器，正式交付方式是“手工安装指南 + 上线核对清单 + 必要脚本”；不得把当前开发机路径当作正式服务器前提。

使用对象

业务执行人员发起事务码任务、查看执行进度、接收钉钉通知、下载或追溯结果。
配置维护人员维护工厂、业务范围、事务码、事务码与工厂规则、定时任务。
系统管理员按手工安装清单部署 SapWebLauncher、配置 SAP 登录信息、初始化 SQLite、核对运行目录、检查队列和服务状态。

系统边界

安全边界：浏览器页面不保存、不接收 SAP 密码；钉钉 appKey、appSecret、agentId 和 SAP 登录配置只允许保存在服务器本机环境变量、config.local.json 或 DPAPI/Windows 凭据管理器中，不返回前端，不提交 Git。
范围V2 当前支持不做或后续再做
事务执行ZFI072A 优先打通；其他事务码可配置展示，但脚本未验证前不作为生产自动化承诺。不并发操作同一个 SAP GUI 桌面会话。
配置源SQLite 是当前主配置源，页面从 API 读取。SQL Server/PostgreSQL 可作为后续迁移目标。
身份与通知页面可从对方平台 URL token 解析钉钉 ID 和姓名；执行页复选框勾选时使用联调默认 11464769，取消勾选时必须使用本次 URL token 的钉钉 ID，未解析到钉钉 ID 则禁止提交。正式身份应由公司门户 URL token 或 SSO 交给 API 侧验签确认。

页面入口

用户打开正式入口 https://fi_automation.srv.lstech.com/rpa/ 后进入本地操作台；兼容排障入口保留 http://10.0.41.158:6174/rpa/。所有真实配置、执行和历史数据都通过服务器本机 http://127.0.0.1:8080 的 API 获取，并由 D:\RPA\gateway\rpa-gateway.js 代理到当前访问域名的 /rpa/api/*。当前前端入口由 index.html 和同目录 assets/js/*.js 共同组成；运行目录缺少 assets/js 时，页面可能白屏、下拉不刷新或按钮无响应。

3

执行任务

执行任务是 V2 的核心功能。页面提交后，API 创建 run，SQLite 记录参数快照，后台串行 worker 领取任务，SapWebLauncher 调用 VBS 和 SAP GUI 执行，结束后回写状态和通知。

ZFI072A 当前业务规则

项目说明
事务码ZFI072A，当前优先打通的采购价月表自动化事务。
输入参数年度、周、工厂列表、业务范围、备注等由页面/API 传给执行器，再由执行器传入 VBS。
工厂来源来自 SQLite 配置中的事务码规则和业务范围，不允许在 VBS 中硬编码固定工厂。
成功判断当前以 VBS 完成流程、SAP 状态栏消息、脚本退出码和执行器记录为依据；若无明确 SAP 状态栏消息，通知文案按“自动化已跑完”表达，不夸大成功。
结束清理每个任务完成后应通过 SAP GUI 执行清理逻辑，例如返回或 /NEX，避免服务器桌面堆积窗口。

排队、进度和日志

提交入队页面调用 POST /api/runs，传入事务码、工厂、操作人、钉钉 ID 和通知目标。
排队等待API 写入 runs.status=queued，页面显示 runId、前方任务数和排队状态。
串行执行后台 worker 将任务改为 running，同一交互式 SAP GUI 桌面一次只执行一个任务。
日志回写VBS stdout、SAP 状态栏、输出文件和通知结果写入 run_logs、run_files。
页面轮询页面通过 GET /api/runs/{runId} 轮询状态，把 API 日志合并到黑底日志框。
黑底日志框说明：页面内存中只保留当前会话展示用即时日志；真正持久日志在 SQLite。刷新页面后，应按 runId 或历史列表重新从 API 读取。

多工厂拆批与失败重跑

当 ZFI072A 一次选择多个工厂时，推荐按“父 run + 工厂子 run”执行。父 run 表示用户的一次业务请求，子 run 表示每个工厂的实际执行结果。这样可以避免 A、B、C 分批执行时只有 B 失败，却无法准确追溯或重跑。

状态含义用户处理
success所有工厂执行完成。查看日志、文件和钉钉汇总。
partial_failed部分工厂成功，部分工厂失败。优先使用失败工厂重跑，不重复执行已成功工厂。
failed任务整体失败或所有子任务失败。按异常 SOP 检查 SAP 登录、脚本、工厂数据量或输出文件。
重跑失败工厂POST /api/runs/{parentRunId}/rerun-failed 根据失败工厂创建新父 run。只重跑失败工厂，保留原 run 审计记录。

跨事务链路与 result 传参

对于“先跑报表 A、报表 B，计算 A+B 的最终 result，再把 result 和页面工厂入参一起传给报表 C”的场景，V2 应采用父子 run 或 chainRun 编排。父 run 表示一次链路请求，子 run 分别表示 A 取数、B 取数、result 计算、C 执行。

步骤责任方数据要求
A/B 报表取数后端通过本地 SAP NCo 报表取数工具、ZFM_NCO_SUBMIT 或等价服务取回 list/spool 数据。原始 A/B 结果必须关联 runId 保存，不能只写进页面黑底日志。
result 计算后端或后台 worker 做清洗、匹配、合并、冲突处理和空值处理。必须明确字段映射：A 哪些字段、B 哪些字段、合并公式、格式转换、空值规则和冲突规则。
result 落库/落盘小结果写 SQLite 结构化字段；大结果写 outputs/<runId>/result-for-C.json、CSV 或 XLSX。C 不从页面临时状态、截图或黑底日志推断 result，只接收 resultId 或 resultFile。
C 执行若 C 可后台执行，优先 NCo/ABAP；若必须操作 SAP GUI，则 SapWebLauncher 串行调用 C 的 VBS。C 入参包含页面工厂参数 + resultId/resultFile，大结果不得塞进 URL 或命令行。
重跑可重跑失败步骤。C 重跑必须绑定同一版 A/B result，或先重新执行 A/B 生成新版 result，不能混用旧 result。
链路门槛：C 只能在 A/B 都成功且 result 必填字段校验通过后执行。A/B 取数失败、result 缺字段或 C 入参校验失败时，链路状态应为 failed 或 partial_failed，不得误标成功。
4

基础配置

基础配置采用后台管理风格，目标是高效维护数据。页面只在 API 在线时允许新增、编辑、删除；离线时仅显示示例或缓存数据。

工厂与业务范围

配置项用户维护内容影响范围
工厂配置工厂代码、名称/说明、所属业务范围、排序、启停。影响事务码规则、执行页工厂列表、定时任务工厂范围。
业务范围配置业务范围 ID、名称、短名称、包含工厂、部分事务专用业务范围或工厂覆盖。执行任务时根据事务码和业务范围自动带出工厂。
事务码配置事务码、名称、模块、阶段、参数、超时秒数、重试次数、启停。影响工作台卡片、执行任务列表、统计排行和定时任务可选项。

事务码与工厂/业务范围规则

规则用于定义某事务码默认选择哪个业务范围，以及最终传给 VBS 的工厂列表。用户选择业务范围后，页面应自动带出对应工厂，并允许在规则维护中增删工厂。最终执行时以事务码规则解析出的工厂列表为准。

日期范围事务：ZFIR034 只接收 period 和 weekEnd，不接收工厂或业务范围，也不要求用户手工输入周次。页面、API、定时任务触发器按运行时服务器系统日期计算上一完整自然周，周一作为开始日期、周日作为截止日期；VBS 在 SAP 选择屏幕写入 S_BUDAT-LOW/HIGH，并按最终开始日期推导周次写入 P_WEEK。例如系统日期为 2026-07-02 时，执行日期范围为 2026.06.22 至 2026.06.28，P_WEEK=26。钉钉通知只展示该日期范围。
配置源规则：API 在线时，配置来自 SQLite；页面不应以旧静态数组作为生产配置依据。API 离线时的 fallback 只用于演示和只读预览。

删除、停用和前端刷新

工厂删除后，后端可能采用软删除方式返回 enabled=false。前端应过滤停用工厂，并同步清理业务范围、事务码规则里的停用工厂引用，因此用户删除后页面不再显示该工厂，也不会继续参与执行。

操作行为注意事项
新增/编辑调用对应配置 API，保存后刷新 GET /api/config。保存失败时不得只改页面内存。
删除工厂API 可软删除，页面过滤停用项。删除后如仍出现，先检查 API 是否返回 enabled=false 和前端过滤逻辑。
停用事务码/规则不再作为可执行生产入口展示或执行。历史记录仍保留，用于审计。
5

统计报表与执行历史

统计报表用于按时间周期查看自动化运行效果。历史列表用于追溯每次 run 的事务码、工厂、耗时、状态、结果摘要、日志和输出文件。

统计指标口径

指标口径来源
执行总次数统计周期内 run 总数。/api/reports/execution 的 summary.totalRuns
成功率成功次数除以总次数，页面显示百分比。summary.successRate
平均耗时周期内平均执行耗时。summary.avgDurationSeconds
节省工时当前页面定义为累计自动化实际运行耗时，不再按人工估算。summary.totalDurationSeconds
事务码排行按事务码展示执行次数、成功、失败、成功率、平均耗时。transactionRanking

历史与审计

执行历史来自 GET /api/runs，日志详情来自 GET /api/runs/{runId}。如果页面刷新，黑底日志框中的即时日志会消失，但历史 run、后端日志和输出文件仍可从 SQLite/API 读取。

导出报表：页面导出的是当前历史/统计视图数据，适合业务人员留档；生产审计仍以 SQLite 中的 runs、run_logs、run_files 为准。

A/B 报表取数合并后驱动 C

如果后续要先读取其他 SAP 报表 A、报表 B，再将 A+B 的最终结果 result 作为报表 C 的输入，推荐由后端编排完成，不把复杂取数和计算塞进 VBS。

页面提交页面只提交工厂、期间、事务链路等业务参数，API 创建父 run。
A/B 取数后端通过本地 NCo 报表取数工具或 ZFM_NCO_SUBMIT 以 BACKGROUND_SPOOL 方式取回 A、B 的 list/spool 数据。
后端计算API 或后台 worker 清洗、匹配和汇总 A/B 数据，生成最终 result。
结果落盘小结果可写 SQLite；大结果应保存到 outputs/<runId>/result-for-C.json、CSV 或 XLSX，并在 run 参数中只传 resultId 或 resultFile。
驱动 C如果 C 可后台执行，继续由 NCo/ABAP 调用 C；如果 C 必须操作 SAP GUI，则 SapWebLauncher 串行调用 C 的 VBS，把页面工厂参数和 resultId/resultFile 一起传入。
设计边界：VBS 只负责把工厂和 result 文件/编号填入 SAP GUI，不负责 A/B 报表取数、复杂合并、数据清洗或重试审计。大结果不要放进 URL 或命令行，避免超长参数和日志泄露。
6

定时任务

定时任务用于提前保存周期性执行配置，例如周一固定执行某事务链路。页面负责维护配置，真正无人值守执行必须由后端常驻服务、任务计划程序或调度器承接。

保存规则

字段说明
任务 ID/名称新建时自动生成或由用户填写，用于列表和审计。
事务码从已启用事务码配置中选择。
业务范围/工厂根据事务码规则和业务范围自动计算工厂。
执行时间/频率用于后续调度器决定何时创建 run。
通知开关控制开始、成功、失败等通知策略。

无人值守执行

重要：静态页面本身不能在无人值守时自动执行 SAP。上线时必须让 SapWebLauncher 或独立调度器读取定时任务配置并创建 run，同时确保 Windows 执行账号已登录交互式桌面。

如果定时任务执行 A/B/C 跨事务链路，调度器创建的是链路父 run，而不是单个事务 run。A、B、result 计算和 C 应分别记录子 run 或步骤状态，便于失败后只重跑失败步骤并追溯 result 版本。

7

钉钉通知

通知由后端 API 发送，不由 VBS 进入 SAP 再调用函数，也不由浏览器直接持有密钥。这样可以减少 SAP GUI 占用时间，也避免前端泄露 appSecret。执行页“勾选固定通知 11464769”只决定本次收件人 ID；真正发送还要求服务器本机配置 DingTalk OpenAPI 的 baseUrl、appKey、appSecret、agentId。

推送前提：如果 run 已成功但没有收到钉钉，优先查看该 run 日志。日志出现 sap dingtalk openapi skipped: missing ... config 时，说明 SAP 执行成功但服务器缺少钉钉发送凭据，不是勾选框或事务脚本失败。

通知对象

来源当前规则上线规则
页面执行人通知目标由执行页“勾选固定通知 11464769”复选框决定：勾选时提交 11464769；取消勾选时提交本次 URL token payload 中解析出的钉钉 ID，字段兼容 Account/Ddid/ddid/DingTalkUserId/UserId；取消勾选且未解析到钉钉 ID 时前端禁止提交，POST /api/runs 也不会写入空通知人。该字段只是接收人，不包含发送凭据。应由公司门户 URL token 或公司 SSO 传给 API，并在后端验签后写入 run 操作人字段。
后台定时任务可使用任务配置中的通知目标或默认负责人。应支持配置任务负责人、业务群或机器人绑定。

异常表现处理方式
本地 API 未启动页面显示 API 不可用、配置只读、无法保存或执行。运行 D:\RPA\bin\SapWebLauncher.exe --serve 或上线步骤中的启动 API 脚本；当前正式入口是 https://fi_automation.srv.lstech.com/rpa/，兼容入口是 http://10.0.41.158:6174/rpa/。
HTTPS 网关未启动域名页面无法访问，但 http://127.0.0.1:8080/api/health 仍正常。运行 powershell -ExecutionPolicy Bypass -File D:\RPA\gateway\start-rpa-gateway.ps1，确认 0.0.0.0:443 和 0.0.0.0:6174 均由本项目 rpa-gateway.js 监听。
API base 缓存漂移正式域名页面能打开，但配置、执行或历史接口请求仍打到旧 IP、旧端口、127.0.0.1 或旧 /charge。网关必须注入 window.SAP_RPA_API_BASE = window.location.origin + "/rpa" 并覆盖 localStorage.sapRpaApiBase；前端优先使用网关注入值。验收时用浏览器开发者工具确认请求为 https://fi_automation.srv.lstech.com/rpa/api/*。
证书异常443 端口可连接，但浏览器出现证书不受信任、域名不匹配或过期告警。检查证书 SAN 是否包含 *.srv.lstech.com，有效期是否覆盖当前日期，客户端是否信任内部 CA；确认 D:\RPA\certs\lstech.com 私钥、PFX 和 passwd.txt 仅执行账号、Administrators、SYSTEM 可读。
SAP 登录失败run 失败，日志出现登录或连接错误。重新运行 SAP 登录配置步骤，在服务器执行账号下生成 DPAPI 配置。
工厂数据量过大单个工厂执行时间过长，可能超过默认超时。提高事务码超时秒数，按工厂拆批执行，失败后只重跑失败工厂。
VBS 未执行或脚本错误run 无 SAP 步骤日志、退出码异常或标准输出为空。检查脚本路径、VBS ASCII/WSH 格式、SAP GUI Scripting 权限和当前桌面会话。
输出文件缺失任务成功但 run_files 无记录。检查 VBS 保存按钮、导出路径、文件权限和执行账号目录。
通知失败任务执行完但未收到钉钉消息；run 日志可能出现 sap dingtalk openapi skipped: missing baseUrl/appKey/appSecret/agentId config。在运行目录 D:\RPA\config.local.json 或服务器环境变量中配置 DingTalk OpenAPI 的 baseUrl、appKey、appSecret、agentId，然后只重启 D:\RPA\bin\SapWebLauncher.exe --serve；同时确认 run 的 ding_talk_user_id 是目标用户，例如联调默认 11464769。
脚本执行策略拦截PowerShell 报未签名脚本或 MachinePolicy=AllSigned。优先使用保留的 `.bat` 入口配置 SAP 登录；其他部署步骤按 runbook 手工执行，并保留命令输出用于排错。
源码已更新但线上仍是旧逻辑GitHub 或 D:\RPA\RpaProject 里有修复，但网页执行日志仍显示旧参数、旧事务脚本或旧错误。检查 D:\RPA\bin\SapWebLauncher.dll 是否来自最新 publish，D:\RPA\transactions 是否已同步，API health 的 runtimeRoot 是否为 D:\RPA，并确认只重启本项目执行器。
A/B 取数失败链路父 run 停在前置报表阶段，C 未执行。检查 NCo/RFC 登录、目标报表权限、spool/list 输出和 ZFM_NCO_SUBMIT 返回消息。
result 缺字段A/B 都返回但 C 入参校验失败。检查字段映射、空值规则、冲突规则和 result 文件；不得让 C 从日志或页面状态猜值。
C 重跑版本不一致C 使用了旧版 result 或混用了不同批次 A/B 输出。重跑 C 时绑定同一版 resultId/resultFile，或重新执行 A/B 生成新版 result 后再执行 C。
